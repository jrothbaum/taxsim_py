    Performance

    The default engine is the compiled calculator (engine="rust"). On a mixed 42-state batch of one million rows, including marginal rates, it takes 0.46 seconds and 1.1 GiB RAM; the Python engine (engine="python", the reference implementation) takes 7.13 seconds and 2.8 GiB. A lazy input streams into any Polars sink with memory that depends mainly on the thread count and hardly on the number of rows (see below). Results depend on the data and hardware.

    Streaming a file

    calculate_taxes(pl.scan_parquet(path), year=2022, mtr=85).sink_parquet(out) runs the same plan without loading the file. On 4 million rows without marginal rates (about 1.0 s, 1.6 GB with 16 threads) and 16 million rows (3.3 s, 2.6 GB), memory depends mainly on the number of Polars threads (it grew from 1.6 GB to 2.6 GB for four times the rows): with POLARS_MAX_THREADS=8 the 16 million rows take 3.7 s and 1.4 GB, and with 4 threads 6.0 s and 0.76 GB.

    Python engine

    On Polars 2.0.0 with the in-memory engine, a mixed 42-state batch of one million rows takes 7.18 seconds and 2.09 GiB RAM. The streaming engine takes 8.34 seconds and 2.50 GiB on the same input. Results depend on the data and hardware.

    Memory Controls

    batch_rows limits input rows per calculation batch; max_year_workers limits concurrent batches and state-plan collection:

    calculate_taxes(df, batch_rows=50_000, max_year_workers=4)

    Reducing either limit can lower peak RAM, especially when many rows belong to one state. Runtime varies with the workload. The full input and output frames still occupy memory proportional to the total row count.

    Execution Strategy

    Small mixed-state batches materialize each federal feedback pass once, then collect independent state plans with up to eight Python workers. Larger or mixed-year workloads use parallel API batches; each batch collects its states serially to avoid nested worker pools. A single state plan is collected directly. max_year_workers=1 disables both levels of Python parallelism.

    Each plan uses the configured Polars engine. The package does not change POLARS_MAX_THREADS or engine affinity. Set POLARS_MAX_THREADS before importing Polars to tune its thread pool independently of the Python workers.

    For local comparisons, scripts/benchmark_polars_version.py times complete calculations, and scripts/benchmark_streaming.py screens streaming collection strategies in bounded subprocesses with output verification.

    Run the Benchmark

    Use a Python environment with polars==2.0.0, pyyaml and psutil to reproduce the table. With that environment activated:

    POLARS_MAX_THREADS=16 python scripts/benchmark_comparison.py \
  --engines taxsim_py taxsim --polars-engines in-memory streaming \
  --rows 1000 10000 15000 100000 200000 500000 1000000

    Use --engines policyengine --policyengine-rows 1000 10000 15000 100000 in an environment with PolicyEngine's dependencies, or --batch-rows 50000 --workers 4 to benchmark memory controls. The Linux harness monitors process-tree RAM with an 8 GiB budget, a 2 GiB available RAM reserve and a 600-second timeout. It stops a measurement at a limit and skips larger samples. These are monitored safeguards, not a hard memory quota.
