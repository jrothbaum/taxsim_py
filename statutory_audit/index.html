    Audit of the statutory side

    Statutory mode departs from TAXSIM only where TAXSIM is known to be wrong. The rows in statutory_corrections.md are the errors found by reading TAXSIM's source and testing it, so each is a known bug. Only parameter errors, where a number in TAXSIM's tables differs from the published value, need a source to confirm the published number. Logic errors (a variable never set, a typo in a condition, a result overwritten) need nothing more. Where a check shows TAXSIM's behavior is not actually wrong (a modelling choice, or a rule the inputs cannot decide), statutory mode is moved back to TAXSIM's behavior in both modes: the switch is removed (a switch exists only to let TAXSIM mode override the correct behavior to reproduce a bug) and listed at the end.

    • Switches: 446. Logic errors (no confirmation needed): 378. Parameter errors verified against a primary source: 40; partly verified: 27; still to verify: 1. Switch removed because TAXSIM's behavior is not a bug: 4.
    • Switches whose flip changes at least one household in the sample: 163. The rest change nobody in the sample.

    How the impact was measured: for each switch, statutory mode is run on CPS households (40 per state, law years 1985, 2000, 2012, 2022 and 2025) with only that switch set to TAXSIM's behavior. "Changed" counts households whose federal or state tax moves by more than $1; "average" is the mean move for those households (scripts/audit_switch_impact.py). Verdicts live in docs/data/statutory_audit_status.yaml; this page is built by scripts/build_audit_ledger.py. The type column is a first sort by the wording of each row and may misfile a few.

    The last column is the check against the compiled TAXSIM for logic errors (scripts/confirm_logic_switches.py, results in docs/data/logic_switch_confirmation.csv): the CPS households that the switch changes are run through the compiled program, and the column says how often it agrees with taxsim mode and with statutory mode. "Not reached by the CPS sample" means no sampled household (up to 800 per state in 17 law years) has the situation the rule covers; those rules rest on TAXSIM's source and on the oracle comparisons made while building taxsim mode.

    Status: logic = nothing more to confirm; verified = the published value matches a cited source; partial = confirmed in part; unverified = a parameter error whose published value has not been checked yet.
